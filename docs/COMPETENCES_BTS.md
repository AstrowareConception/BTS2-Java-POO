# Correspondance avec les compétences BTS SIO SLAM

Ce document fournit des repères pédagogiques ; il ne remplace ni le référentiel ni les documents académiques en vigueur.

| Attendu du bloc 2 SLAM | Activités et preuves possibles |
|---|---|
| Analyser un besoin et son contexte | user stories, règles, critères d’acceptation, cas limites |
| Participer à l’architecture | couches, ports/adaptateurs, justification local/distribué |
| Modéliser une solution | diagrammes de classes, séquences, modèle relationnel |
| Exploiter un framework | JavaFX et Spring Boot |
| Développer des composants | domaine, services, repositories, contrôleurs |
| Mettre en œuvre des échanges | HTTP, JSON, client Java, API REST |
| Utiliser des composants d’accès aux données | JDBC, JPA, requêtes paramétrées |
| Intégrer les versions | Git, branches courtes, CI Maven |
| Réaliser les tests | JUnit, tests paramétrés, intégration, acceptation |
| Documenter | README, Javadoc ciblée, guides, schémas |
| Maintenir | tickets correctifs, refactorisations, tests de non-régression |
| Gérer les données | SQL, contraintes, transactions, migrations, sauvegarde |
| Prendre en compte la cybersécurité | validation, moindre privilège, secrets, logs, TLS |

## Traces à conserver

- commits personnels et revues ;
- tickets avec besoin et critères d’acceptation ;
- captures de tests et rapports de CI ;
- diagrammes datés et cohérents avec le code ;
- décisions techniques argumentées ;
- procédure reproductible d’installation ;
- preuve d’un correctif ou d’une évolution.

L’épreuve E5 s’appuie sur deux réalisations. CinéDesk est conçu pour devenir une réalisation substantielle, mais l’étudiant doit situer précisément ce qu’elle prouve et ce que la seconde réalisation complète.
