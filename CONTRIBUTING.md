# Contribuer aux exercices

## Étudiants

1. Créer une branche courte : `prenom/serie-01-atelier-02`.
2. Ne modifier que les fichiers nécessaires à l’atelier.
3. Faire des commits portant une intention précise.
4. Exécuter les tests concernés avant de demander une revue.
5. Ne jamais pousser de secret, de base personnelle ni de correction récupérée ailleurs.

## Proposition de correction du dépôt

Une pull request doit préciser :

- le problème reproduit ;
- l’atelier concerné ;
- la modification proposée ;
- la commande de validation ;
- l’absence de solution complète dévoilée par erreur.

## Style

- Code, commits et documentation peuvent employer le français ; rester cohérent dans un même module.
- Noms de classes en PascalCase, méthodes et variables en camelCase, constantes en majuscules.
- Pas de méthode vide silencieuse : utiliser un `UnsupportedOperationException` explicite dans un starter.
- Une règle non évidente doit être testée et documentée près de son contrat.
